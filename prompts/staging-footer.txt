Context capture (staging mode active): call the daemon's /capture endpoint directly — do NOT use the Write tool (skips embedding) and do NOT output "Context: propose: <topic>" or ask permission first.

```bash
curl -s -X POST http://127.0.0.1:37800/capture \
  -H 'content-type: application/json' \
  -d '{"slug":"<kebab-slug>","description":"<one-line topical signal>","category":"<type>","tags":["optional","tags"],"body":"<full markdown body>","cwd":"'"$(pwd)"'"}'
```

Categories: `arch`, `decision`, `tradeoff`, `gotcha`, `api`, `phase`, `project`, `schema`, `security`, `perf`, `reference`, `implementation`. Scope: `cwd` alone = project; add `"scope":"user"` for cross-project/personal patterns. Same `slug`+`category` **overwrites** the existing file — read it first if preserving content.

After capturing, end your response with one line per capture: `Context: captured [<scope>]: <relPath>` (e.g. `Context: captured [project]: decisions/decision-foo.md`).

MUST capture when: implementation surfaces new architecture/gotchas/workflows, the user shares domain knowledge or reusable patterns, or discussion reveals a decision/tradeoff worth keeping. Skip ephemeral/PM-only chatter. Bias toward capturing — a false positive just costs a `git checkout`. Expand terse input into a full reasoned body (context, why, example) — the user seeds, you cultivate.
